# 導入・操作手順（v0.5.3）

## 1. アプリを配置する

Windows 10 バージョン2004以降／Windows 11 x64を使用します。[Releases](https://github.com/Long0823-1/TS-Encode-Flow/releases/latest) のWindows x64用ZIPをすべて、今後移動しないフォルダーに展開し、`TS-Encode-Flow.exe` を起動します。ZIP内から直接実行しないでください。`Worker`、`Tools`、DLLも必要です。.NET・MAUIの実行ファイルは配布物に含まれます。

GitHubの「Code → Download ZIP」はソースです。ビルド済みZIPが手元にない場合は[ビルド手順](BUILD.md)から作成します。

## 2. 変換ツールと保存先を設定する

**設定 → すべてダウンロードして適用**を押すと必要なツールを自動取得し、設定へ反映します。個別ダウンロード、中止、各ツールのライセンス文書の表示にも対応します。手動で導入する場合は次を指定して「設定を保存」を押します。

| 項目 | 指定するファイル |
| --- | --- |
| FFmpeg（すべての方式で必須） | `ffmpeg.exe` |
| ffprobe（すべての方式で必須） | `ffprobe.exe` |
| AMDを使う場合 | `VCEEncC64.exe` |
| NVIDIAを使う場合 | `NVEncC64.exe` |
| Intelを使う場合 | `QSVEncC64.exe` |
| TS内の日本語番組情報を解析する場合（任意） | EDCB x64の `EpgDataCap3.dll` |

画面内の各ツールの配布元リンクから入手できます。CPUはFFmpegを使います。GPU方式にもFFmpegとffprobeが必要です。GPUドライバーと、そのGPUが対応するコーデックを使用してください。

「動画の保存先」と「ファイル名マクロ」も設定します。例：`{Start:yyyyMMdd_HHmm}_{Channel}_{Title}`。元TSと同じ名前になる場合を含め、既存の出力は連番で保持します。

## 3. AMDで変換する

1. **プリセット**を開き、「変換方式」でAMD / VCEEncCを選びます。
2. 最初は「毎日の番組・バランス」を選択します。解像度は1280×720、H.264のプリセットです。
3. 用途に合わせてアニメ・映画などへ変更できます。「詳細・カスタマイズ」で解像度、画質、Yadif／Bwdif、音声、字幕などを調整し、自分用のプリセットとして保存できます。
4. **＋ TSを追加**から録画済みTSを選びます。複数選択、フォルダー追加、ドラッグ＆ドロップにも対応します。
5. **変換キュー**で進捗を確認します。録画中のTSは書き込み終了まで待機します。完了後の「出力先」で保存場所を開けます。

![ダッシュボード](maui-dashboard.jpg)

追加済みジョブは追加時のプリセットを保持します。設定を変える場合は対象ジョブを中止し、「プリセットを変更」で新しい設定を適用してから「再試行」します。

## 自作プリセットを新規追加する

1. **プリセット**画面の上部で変換方式を選びます。
2. **「＋ 自作プリセットを追加」** を押します。
3. 名前、コーデック、解像度、画質、フィルタ、音声・字幕などを設定します。
4. 画面下部の **「自作プリセットを追加」** で保存します。

保存後は「カスタム」に表示され、そのプリセットが選択されます。編集画面で変換方式を変更して保存した場合も、保存した方式の一覧へ切り替わります。既存設定をベースにする場合は、従来の「詳細・カスタマイズ」を使用できます。

## 4. 中止したTSを再実行する

- 同じ設定でやり直す場合：キューの「再試行」を押します。
- 現在選んでいるプリセットでやり直す場合：中止が完了した後、同じTSを再選択します。
- v0.2.2ではキャンセル済み・完了済みの履歴があっても手動で新規追加できます。待機中・変換中の同じTSは重複追加されません。
- フォルダー監視は履歴を使って繰り返し投入を防ぎます。監視対象を意図的に再実行するときも、手動追加か「再試行」を使います。

元TSと過去のキュー履歴は保持します。

## 5. 字幕・番組情報・DRCSを保存する

字幕保存と番組情報メタデータ保存をプリセットで有効にします。MP4はmov_text、MKVはASSの切り替え可能な字幕として保存します。放送時の配置・色などを完全再現する方式ではありません。

TSの隣にEDCBの `.ts.program.txt` または `.program.txt` がある場合は、一緒に残してください。番組名・日時・局名に利用します。字幕PIDの宣言だけがあり実データがない録画は、字幕を作らず正常完了します。

既定の「止めて補正する」設定で、未対応DRCSのため止まった場合：

1. **字幕・DRCS**で字形と前後の字幕文を確認します。
2. 必要なら参考の写真・スクリーンショットを選びます。
3. 代替文字を入力して「保存して待機中の変換を再開」を押します。

対応表は保存され、次の録画にも利用されます。自動OCRではなく手動で照合・入力する機能です。

![字幕・DRCS（検証用サンプル）](maui-drcs.jpg)

### 字幕の問題を無視して進めたい場合

新規プリセット、または「詳細・カスタマイズ」の音声・字幕欄で「字幕エラーを無視して続行」をONにして保存します。未対応のDRCSは `�` に置き換え、字幕の抽出・格納に失敗した場合は字幕なしで続けます。完了時に「字幕の警告あり」と表示し、ログと出力の `.encode.json` に内容を残します。

既に「DRCS入力待ち」などで停止しているジョブは、**変換キュー → 字幕の問題を無視して再試行**で、そのジョブだけを続行できます。字幕が欠ける可能性があるため、正しい字幕を残したい録画には補正入力を使用してください。元TSは保持します。映像・音声エラーやキャンセルを無視する設定ではありません。

## CMをカットする／CMを残して区分を付ける

1. プリセットの新規作成・カスタマイズで「CM・タイムリスト」を開きます。
2. 「CMを残してチャプター・タイムリスト」または「CMをカットして本編をつなぐ」を選びます。
3. 初回は「変換前にCM候補を確認する」をONにします。保存してTSを追加します。
4. CM確認待ちになったら、サイドメニューまたはキューの「CM・タイムリストを確認」を開きます。
5. CMの開始・終了を hh:mm:ss.fff または秒数で入力します。追加・削除、EDL／Trim AVSの読み込みもできます。
6. 本編／CMの一覧を確認し、出力方法を選んで「この区間・出力方法で確定して続行」を押します。CMなしと判断した場合はCM区間をすべて削除して確定できます。
7. 完了した動画のチャプターと、隣の `.cm.csv` を確認します。CSVには入力・出力それぞれの時刻を記録します。カットしたCMの出力時刻は空欄です。

### 区間ファイルを用意する場合

TSの隣の `番組.ts.edl`、`番組.edl`、`番組.ts.trim.avs`、`番組.trim.avs` を探して読み込みます。EDLは「開始秒 終了秒 0」でCM区間を指定します。コード3のCM指定も読み込めます。コード1（ミュート）と2（シーン）はカット対象にしません。

```text
300.000 330.000 0
900.000 960.000 0
```

join_logo_scp系のAVSは、本編として残すフレームを読み込みます。次の例では0～899、1800～2699を残します。終端フレームも含みます。

```text
Trim(0,899) ++ Trim(1800,2699)
```

AVSは実行しません。Trim以外の式や関数を含むスクリプトは受け付けません。基準FPSはプリセットで指定でき、空欄なら入力FPSを使います。別の映像・Amatsukazeで前処理後の映像・VFR化後のTrimは、そのまま元TSへ流用できません。

### ロゴ・無音・シーンチェンジで自動解析する

1. 設定で「CM解析 · chapter_exe / join_logo_scp / AviSynth」と「logoframe」をダウンロードして適用します。一括ダウンロードでも取得できます。
2. プリセットをカスタマイズし、CM処理をチャプターまたはカット、区間取得方法を「Amatsukaze方式でCM候補を自動解析」にします。
3. 最初は「変換前にCM候補を確認する」をONのまま保存します。
4. TSを追加します。局別ロゴが未登録で範囲もない場合、「ロゴ範囲指定待ち」になります。「放送局ロゴ」またはキューの「ロゴ範囲を指定」を開き、本編のロゴが見える秒数でプレビューを表示し、ロゴを囲んで保存します。同じ局・元解像度で範囲とLGDを再利用します。
5. 無音／シーンチェンジ検出・区間判定後、「CM・タイムリスト」で確認・修正して確定します。

Amatsukaze本体は使用しません。CM解析に必要な構成ツールだけを利用します。未登録局のロゴは初回に指定した範囲から生成し、設定から対象局のLGDを指定することもできます。ロゴなし解析はプリセットで明示的にONにしてください。自動生成・解析に失敗したら停止し、無断でロゴなし方式へ変更しません。

元TSを直接解析します。全編の解析専用動画は作成せず、インデックスの全フレーム時刻をFFmpeg側と照合して先頭のずれを補正します。インデックスは設定フォルダーの `Commercials/IndexCache` に保存・再利用します（約30分の実TSで約58MiB、解析中は作業コピーも使用）。初回だけ録画フォルダーに `.lwi` を一時生成するため書き込み権限が必要です。既存の同名インデックスは退避・復元します。映像を読む解析時間は必要です。途中のVFR・ドロップ等は停止します。末尾だけの小さな時刻差は最後の1秒を保持して扱います。自動判定の正解は保証できないので、実際の映像とタイムリストで確認してください。

CMをカットすると、CM内の字幕は除き、本編に重なる字幕は残した区間の時刻へ詰めます。音声コピーは使わずAACへ再変換します。CMカットと任意FPS指定の併用はできません。出力方法を確認画面でカットへ変更した場合も、そのジョブでは音声コピーとFPS指定を解除します。CPUカットはFFmpeg 9で検証しました。

録画後BATにも作成時のCM設定が保存されます。確認ONのBATでは録画後に「CM確認待ち」で止まるのが正常です。自動確定を使いたい場合は、検証した区間ソースと確認OFFのプリセットでBATを作り直します。

## 6. EPGTimerの録画後に自動変換する

1. 手動で短いTSの変換を確認します。
2. **自動化**で録画後専用の変換方式とプリセットを選択します。手動変換の選択とは独立しています。
3. 「このプリセットで録画後BATを作成」を押し、保存します。
4. 生成された `.bat` と `.bat.profile.json` を同じフォルダーに置きます。
5. EPGTimerの対象の録画設定で「録画後実行」に生成BATを指定します。予約・プリセットごとの設定への反映方法はEDCB版によって異なります。
6. まず1件の録画で、録画終了後にキューへ追加され、出力が作成されることを確認します。

`_EDCBX_DIRECT_` に対応し、録画TSのパスを `FilePath` 環境変数で渡せるEDCB版が必要です。BATはウィンドウを出さずワーカーへ登録します。アプリの画面を閉じても処理しますが、PC自体のスリープ中・電源断中には変換できません。

![録画後BAT設定](maui-automation.jpg)

BATには作成時のプリセット・保存先・マクロを固定します。変更するときはBATを作り直します。アプリを移動したときも作り直してください。EDCBをサービスとして動かす場合は、その実行ユーザーがアプリ・設定・録画先・出力先・GPUにアクセスできる必要があります。

### バックグラウンドの状態を見る・GUIを開く

通常のデスクトップ上では、録画後BATやアプリから起動したワーカーが通知領域にアイコンを表示します。見つからない場合はタスクバーの「隠れているインジケーター」を開いてください。

- ダブルクリック：変換キューを開く。
- 右クリック → GUIを開く：ダッシュボードを表示。
- 右クリック → 字幕・DRCSを開く：字形の補正画面を表示。
- マウスを置く：変換・待機・一時停止・DRCS入力待ちの状態を表示。
- 右クリック → バックグラウンドを終了：常駐を終了。変換中は中止の確認が出ます。待機ジョブは保存されます。再開する場合はGUIの「処理を再開」を使用します。

GUIの×は画面を閉じます。常駐を終了する操作とは別です。GUIが開いているときにトレイから表示すると、同じ設定フォルダーの画面を再利用します。DRCS待ちではバルーンでも通知します（表示はWindowsの通知設定によります）。

EDCBの実行セッションがサービスなどの非対話セッションの場合、トレイは表示できません。通常のアプリから同じ設定フォルダーを開いて確認してください。旧ワーカーはトレイに対応していないため、新版の配布ZIPへ切り替え、既存の録画後BATも作り直してください。

## 7. フォルダー監視と並列処理

**自動化**で監視先、待機秒数、並列数を設定します。録画保存先とは別の出力フォルダーを指定します。TSのサイズ・更新時刻が待機秒数だけ変化せず、書き込み中でもないことを確認して追加します。ネットワーク録画先などでは、録画終了BATによる通知から確認することを推奨します。

並列数はまず1から始め、GPU・CPU・ディスクの余裕を見て増やします。最大8本ですが、GPUの同時セッション数や空き容量による制限があります。

## 8. 更新とトラブル時

v0.2.4以降は起動時と、画面を開いている間の6時間ごとに最新の正式リリースを確認します。新しい版があれば、画面上部に更新案内が表示されます。「更新内容・ダウンロードを開く」からリリース内容と配布ZIPを確認してください。**設定 → アプリの更新 → 更新を確認**でも確認できます。通信できない場合は手動確認欄に理由を表示し、変換は継続します。v0.2.3以前からは最初だけ手動更新してください。

新しい配布ZIPは別フォルダーに全展開し、変換中の処理が終わってから旧アプリ・旧ワーカーを終了して切り替えます。旧版と新版を同時に常用しないでください。配置先が変わったらBATも作り直します。

通常の設定・キュー・ログは `%LOCALAPPDATA%\TS-Encode-Flow` にあります。**設定 → 設定フォルダーを開く**でも確認できます。`--data` で起動した場合は指定先に保存します。バックアップはワーカーも停止した状態で行います。

| 症状 | 確認すること |
| --- | --- |
| ツールが見つからない | FFmpeg・ffprobe・選択したエンコーダーの実ファイルへのパスを保存したか |
| メニュー切り替えでコンポーネントのエラー | v0.2.1以降へ更新。改善しない場合は `ui-errors.log` を確認 |
| 中止したファイルを追加できない | v0.2.2以降へ更新。旧ワーカーが残っていないか確認 |
| 追加したのに開始しない | v0.5.2は追加で自動再開。録画中・更新直後の安定待ち、並列数の上限、CM・DRCS確認待ちとエラーログを確認 |
| GPU変換で失敗する | GPUの対応コーデック・ドライバー・選択ツールを確認。キューの「詳細」でログを見る |
| 字幕がない | 実際に字幕データがあるか、字幕保存が有効か、再生ソフトの字幕選択を確認 |
| 裏で動いているか分からない | 通知領域のアイコンからキューを表示。DRCS入力待ち・一時停止の状態を確認 |
| BATから追加されない | EDCBX直接実行の対応、`FilePath`、profile.jsonの同居、実行ユーザーのアクセス権を確認 |

検証範囲は[検証記録](VALIDATION.md)に記載しています。NVIDIA／Intelの実機変換、すべてのプリセットの組み合わせ、実際の録画終了イベントは未検証です。

## 履歴を消す

変換キューの「履歴をクリア」は終了したジョブの表示を消します。処理中・待機・確認待ちは残ります。元TSや出力動画・ログは削除せず、監視の再登録防止情報も保持します。

## カスタムプリセットを削除する

プリセット画面で変換方式と「カスタム」を選び、対象カードの「このカスタムプリセットを削除」を押します。名前を確認して「削除する」を選択します。標準プリセットは削除できません。選択中のものを削除した場合は同じ変換方式の標準に戻ります。作成済みBATや既存ジョブは保持する設定で動作するため、そちらも変更したい場合はBATを作り直すかジョブを追加し直してください。

## 同名のカスタムを更新する

同じ名前で保存すると既存のカスタムを上書きします。別の変換方式に変えても名前が同じなら同じ1件を更新します。標準プリセットは上書きしません。別の設定として残したい場合は名前を変えてください。

## 登録済みジョブだけプリセットを変える

1. 変換キューで対象を「中止」し、状態が「中止」になるまで待ちます。
2. 「プリセットを変更」を押し、変換方式と名前を見て設定を選びます。
3. 「このジョブに適用」を押し、反映されて画面が閉じるまで待ちます。
4. キューで設定を確認して「再試行」を押します。

他のジョブや作成済みBATは変えません。対象ジョブのCM・字幕の確認状態はリセットします。


### CM解析で「failed to get the video track」が出る場合

v0.5.0では番組情報のデータトラック等があるTSで、FFmpegとCM解析ツールのトラック番号が異なり失敗する不具合がありました。v0.5.1では元TS内のパケット位置と時刻で照合してから選択します。処理中の変換が終了してから画面と旧ワーカーを終了して更新し、失敗したジョブを「再試行」してください。このエラーだけでは書き込み権限の問題とは判断できません。


## 追加後の自動開始

手動追加・録画後BATからキューに登録すると、ワーカーを起動し、一時停止中でも自動再開します。再試行とCM区間の確定でも再開します。既に最終更新から安定待ち時間（既定60秒）以上経っているTSは、書き込み中でないことを確認して次の処理周期で解析を始めます。追加のたびに60秒を待ち直す必要はありません。更新直後や変更を検出した録画は安定確認を待ちます。並列上限とCM・DRCSの確認は引き続き適用します。監視だけで検出したファイルは一時停止を解除しません。


## 自動ロゴ取得に失敗した場合だけ方式を切り替える

1. プリセット編集の「CM・タイムリスト」でCMの出力方法を選び、「Amatsukaze方式でCM候補を自動解析」を選びます。
2. 「ロゴを使わない」はOFFのまま、「ロゴ取得失敗時は無音・シーンチェンジのみで続行」にチェックします。
3. 保存してからTSを追加します。初回の未登録局では範囲を指定します。生成・検出に成功した場合はロゴを使い、失敗時だけ無音・シーンチェンジのみで続行します。

未チェックなら、従来どおり自動ロゴ取得失敗時に停止します。手動LGD指定の失敗は切替対象外です。既存ジョブ・録画後BATへは新しいプリセットを適用し直してください。


## 放送局ロゴの管理（v0.5.4）

「放送局ロゴ」で、局と元解像度ごとに保存済みLGDと範囲を確認できます。キューの履歴を消しても登録は保持します。放送局IDが揃わないTSは局名も使って分離し、局名もない場合は入力パス単位で分離します。他局のロゴを誤って共有しないためです。

未登録局だけプレビューで範囲を指定します。横長ピクセルのTSは正しい縦横比で表示し、範囲を元のピクセル座標へ戻して保存します。プレビューは1フレームだけで、表示秒数を変えられます。元映像内で幅・高さ8ピクセル以上が必要です。録画後BAT経由でも範囲指定待ちを保持し、トレイ通知からGUIを開いて再開できます。ロゴファイルが未生成のまま失敗した場合は、「放送局ロゴ」から範囲を指定し直せます。

CM処理OFF、最初からロゴなし、手動LGD指定では、この初回範囲指定を求めません。


## ロゴを囲んでも「有効画素が少ない」となる場合（v0.5.5）

範囲指定はロゴの位置を伝える設定です。薄いロゴや、周囲に番組テロップが重なる場面では、従来の単色背景の判定が本編を除外し、ロゴのない場面ばかりから生成を試みて失敗する場合があります。

v0.5.5では、通常の生成に失敗した場合だけ、境界画素の70%以上が狭い輝度範囲に集まる背景から再推定します。複雑な背景を無条件に単色扱いする方式ではありません。通常の生成が成功した場合は従来の経路を維持します。

再推定した候補は **「生成ロゴ確認待ち」** になります。「放送局ロゴ」またはキューの **「生成ロゴを確認」** を開きます。番組名や大きなテロップが見えたら **「登録せず範囲を選び直す」** を選び、局ロゴの見えている文字部分などに範囲を絞ってください。局ロゴだけなら **「局ロゴとして保存して再開」** で同じ局の待機ジョブを再開します。確認前の候補は局別LGDとして再利用しません。

改善したlogoframeとGPL-3.0のライセンス・完全な対応ソースを `Tools/CmLogo` と `Worker/Tools/CmLogo` に同梱しています。アプリ管理のロゴツールを使用している場合は同梱版を優先します。手動で別の実行ファイルを指定している場合は、設定から更新版logoframeを取得して適用してください。CM解析用のAviSynth・chapter_exe等は従来どおり設定から取得します。

更新時はGUIだけでなく、タスクトレイのTS Encode Flowも「バックグラウンドを終了」で閉じてから新しい版を起動してください。変換中なら完了を待ってください。旧ワーカーが常駐したままでは新しい生成処理に切り替わりません。

CM処理OFF・最初からロゴなしの設定では候補生成・確認を求めません。生成自体が失敗する場合の無音／シーンチェンジへの切替設定も引き続き使用できます。ロゴ候補の確認待ちを、生成失敗として自動で無視することはありません。
